# Notanda API v1

Source of truth for the client↔server contract. The desktop TS types (`desktop/src/renderer/api/types.ts`) and server Pydantic models (`server/notanda_server/api.py`) both mirror this file by hand — update all three together.

Base URL: `https://<server>` (Caddy → uvicorn on `127.0.0.1:8000`).

## Auth

Every `/v1/*` request: `Authorization: Bearer <api_key>`.
Keys are opaque 43-char urlsafe tokens, issued manually (`python -m notanda_server.keys create <label>`), stored server-side as SHA-256 hex. Meetings are scoped to the creating key. Missing/unknown key → `401 {"detail": "invalid api key"}`.

## Meeting lifecycle

`recording → processing → complete`, or `error` (summary failed after retries; transcript still available).

- `recording` — created, chunks accepted.
- `processing` — `/finish` called; chunks may still be transcribing, summary pending.
- `complete` — all chunks transcribed and summary stored.
- `error` — summary generation failed; `segments` still served.

## Endpoints

### POST /v1/meetings

Create a meeting when the user hits record.

```
Request:  {"title": "اجتماع المنتج" | null, "language": "ar"}   // language: "ar" | "en", default "ar"
Response: 201 {"id": "mtg_k3v9x2m1qa", "title": null, "language": "ar",
               "status": "recording", "created_at": "2026-07-24T09:00:00Z"}
```

### PUT /v1/meetings/{id}/chunks/{stream}/{index}

Upload one standalone WebM/Opus chunk. `stream` ∈ `mic` | `sys`; `index` = 0,1,2,… (client-assigned, 30 s cadence).
Body: raw `audio/webm` bytes (~120 KB @ 32 kbps). Max 10 MB.

```
Response: 204
```

Idempotent: re-PUT of an already-received `(stream, index)` returns `204` without reprocessing (client retries are always safe). Meeting not in `recording`/`processing` → `409`.

### POST /v1/meetings/{id}/finish

No more chunks coming. Body: `{}` (or `{"duration_ms": 1834000}` if the client knows it).

```
Response: 202 {"status": "processing"}
```

Summary is generated by the worker once every chunk is `done`. Idempotent.

### GET /v1/meetings

```
Response: 200 {"meetings": [
  {"id": "mtg_…", "title": "…" | null, "status": "complete",
   "created_at": "…", "duration_ms": 1834000 | null, "has_summary": true}
]}   // newest first
```

### GET /v1/meetings/{id}

```
Response: 200 {"id": "…", "title": "…" | null, "language": "ar", "status": "complete",
               "created_at": "…", "finished_at": "…" | null, "duration_ms": 1834000 | null,
               "summary": {
                 "overview_md": "…",
                 "decisions": ["…"],
                 "action_items": [{"text": "…", "owner": "…" | null}],
                 "generated_at": "…", "model": "claude-haiku-4-5"
               } | null}
```

### GET /v1/meetings/{id}/segments?after_seq=0

The near-live transcript. Client polls every 5 s while recording and while `pending_chunks > 0`.

```
Response: 200 {"segments": [
                 {"seq": 17, "speaker": "me",          // "me" (mic) | "them" (sys)
                  "start_ms": 61200, "end_ms": 66900,  // coarse: chunk_index*30000 + VAD offset
                  "text": "طيب نبدأ بالموضوع الأول"}
               ],
               "last_seq": 17,          // pass back as after_seq next poll
               "pending_chunks": 2}     // chunks not yet transcribed; 0 + status!=recording → transcript final
```

Segments are ordered by `start_ms` (streams interleaved). `seq` is a global monotonic id used only as a polling cursor.

### GET /healthz

No auth. `200 {"ok": true, "queue_depth": 3}`.

## Errors

FastAPI-style: `{"detail": "message"}` with 400/401/404/409/413. Client treats network failure and 5xx as retryable (chunk PUTs), everything 4xx as fatal for that request.
